# 用量与计费总结网页

## 一句话目标

点击桌面端的「计费」入口后打开一个网页，用 GitHub Contributions 风格的日历方格呈现每天的使用次数与费用，并支持查看当日明细和周/月总结。

## 用户价值

当前主窗口只展示「今日已用 + 账户余额」，能回答今天花了多少，但不能直观看到长期使用规律。这个网页需要进一步回答：

- 哪些天使用过，分别用了多少次、花了多少钱？
- 某一天具体做了哪些翻译或问答，各自消耗多少？
- 一周或一个月总体用了多少，主要用在什么场景，趋势如何？
- 这段时间的使用是否高效，有哪些值得回顾的内容？

## 目标体验

### 1. 入口

- 主窗口现有计费区域提供明确的可点击入口，例如「查看用量与账单」。
- 点击后使用系统默认浏览器打开统计网页。
- 网页优先读取当前设备的本地历史；未来接入账号同步后，可扩展为多设备汇总。

### 2. GitHub 风格用量日历

- 以一年或最近若干月为范围，按周排列每日方格。
- 方格颜色深浅表示当天用量，支持在「调用次数」与「估算费用」之间切换口径。
- 悬停方格显示日期、调用次数、估算费用、token 用量等摘要。
- 点击某一天进入当天记录明细。
- 没有使用的日期明确显示为零，不与「数据缺失」混淆。

### 3. 每日记录明细

- 展示当天总调用次数、总估算费用、缓存命中/节省、输入与输出 token 等汇总指标。
- 按时间倒序列出每次记录，包括时间、来源类型、原文或问题、结果摘要、token、费用和缓存状态。
- 支持按翻译、查词、划词翻译、快捷问答等来源筛选。
- 点击单条记录可查看完整内容；默认避免在概览页直接暴露大段原文和译文。

### 4. 自我总结

- 自动生成周总结和月总结，至少包含总次数、总费用、日均费用、最活跃日期、环比趋势和使用来源分布。
- 总结区可提炼高频主题、常见任务和近期使用习惯，帮助用户回顾自己把工具用在了什么地方。
- 统计型总结应由本地数据直接计算；需要 LLM 归纳内容时必须明确标注，并允许关闭，避免为了总结额外产生未知费用。

## 数据与口径

- 第一阶段复用本地 `history-YYYY-MM-DD.jsonl`，以记录中的 `cost_yuan` 和 token 字段为基础，不重复维护一套账本。
- 页面金额默认标注为「本机估算」，不能伪装成模型厂商的官方账单；账户余额仍沿用现有余额接口口径。
- 本地缓存命中可计入使用次数，但费用为零，并单独标识，避免把活跃度与付费调用混为一谈。
- 跨设备统计依赖后续的历史同步能力；未同步前，页面必须明确提示统计范围仅为当前设备。
- 历史字段不足时应向后兼容，缺失项显示为不可用，不能把缺失值当作零参与结论。

## 隐私要求

- 默认本地处理与展示，不为生成统计而上传翻译原文、问题或结果。
- 内容型总结若调用远端模型，首次使用前说明会发送哪些内容、预计产生何种费用，并提供「只做数值统计」模式。
- 页面需支持隐藏内容，仅查看次数、token 与费用；录屏或分享时不泄露敏感文本。

## 分阶段落地

### Phase 1：本地统计页

- 计费入口打开网页。
- GitHub 风格日历方格。
- 次数/费用口径切换。
- 每日汇总与逐条历史明细。
- 周/月数值总结。

### Phase 2：内容回顾

- 来源分布、趋势对比和高频主题。
- 可选的 LLM 周报/月报。
- 数据导出与隐私隐藏模式。

### Phase 3：多设备汇总

- 接入账户与历史同步。
- 区分设备、模型与 API Key 的用量。
- 对照厂商账单或余额变化，提示估算偏差。

## 暂不决定

- 网页采用应用内本地 HTTP 服务、静态页面读取导出数据，还是账号系统中的远程页面。
- 热力图默认按次数还是按费用着色。
- 内容总结使用规则统计、本地模型还是远端 LLM。

这些技术选择留到正式排期时结合账号同步、跨平台支持和数据规模再定，不影响当前产品目标。

## 验收标准

1. 用户能从计费入口一步打开统计网页。
2. 任意有历史的日期都能在日历中看到次数和费用，并可进入当天明细。
3. 日、周、月汇总值与底层历史记录可核对，费用口径有明确标签。
4. 页面能区分无使用、数据缺失、本地缓存命中和真实模型调用。
5. 默认不上传历史内容，敏感原文与结果可隐藏。

## 与现有设计的关系

- 现有 [`../plans/design/billing-balance.md`](../plans/design/billing-balance.md) 继续负责主窗口的「今日已用 + 账户余额」。
- 本计划负责更完整的长期用量分析、历史追溯与自我总结，两者共享同一份费用历史口径。
- 多设备汇总可与 [`account-sync-byok.md`](account-sync-byok.md) 的历史同步能力衔接，但本计划的本地版本不依赖账号系统即可落地。
